# Окоём — интернет-магазин муралов

WordPress + WooCommerce, классическая тема на PHP. Вёрстка заказчика лежит в
`macket/` и нарезается в шаблоны скриптом, а не руками.

## Структура

```
macket/                          вёрстка заказчика как есть, не редактируется
tools/convert.py                 нарезка макета в шаблоны темы
wp-content/themes/okoyom/        тема: шаблоны, ассеты, навигация
wp-content/plugins/okoyom-core/  контент-модель: материалы, таксономии, заявки
docs/                            вопросы к заказчику, решения, инструкции
```

Функциональность живёт в плагине, а не в теме: вёрстка ещё будет меняться,
а модель данных от этого зависеть не должна.

## Запуск

Быстрый путь, без Docker — на машине уже есть PHP 8.5 и MySQL:

```bash
bash tools/setup-local.sh && php tools/seed.php
```

Первый скрипт скачивает ядро WordPress, создаёт базу и подключает тему с
плагином симлинками. Второй ставит WordPress, включает тему и плагин,
заводит страницы, меню и ЧПУ со слэшем на конце — всё, что иначе пришлось бы
кликать в админке. Логин и пароль администратора он печатает при установке.

```bash
PHP_CLI_SERVER_WORKERS=8 php -S 127.0.0.1:8080 -t wp
```

Воркеры обязательны: встроенный сервер PHP однопоточный и на странице с
шестью десятками картинок начинает их терять.

WooCommerce ставится отдельно из каталога плагинов — он нужен для каталога
и карточки товара, к которым мы ещё не приступали.

Вариант с Docker (`docker-compose.yml`) остаётся для сервера и для staging:
там нужен предсказуемый набор версий и Mailpit для писем заявок.

```bash
cp .env.example .env   # заполнить пароли
docker compose up -d
```

## Пересборка вёрстки

Заказчик присылает новую версию макета → кладём в `macket/` → прогоняем цепочку:

```bash
python3 tools/normalize.py && python3 tools/pages.py && python3 tools/convert.py
```

`normalize.py` правит дефекты вёрстки, `pages.py` собирает страницы, которых
нет в макете («Спасибо» и выдача поиска), `convert.py` режет всё в шаблоны темы.
Каждый скрипт идемпотентный: повторный запуск ничего не портит.

После любой правки вёрстки — проверка геометрии, см.
[docs/pixel-check.md](docs/pixel-check.md). Визуал заказчика трогать нельзя,
и это проверяется измерением, а не на глаз.

Скрипт перезаписывает `header.php`, `footer.php` и всё в
`template-parts/static/`. Эти файлы помечены как сгенерированные — править их
руками нельзя, изменения нужно вносить в макет или в правила конвертера.

## Что уже сделано

Вёрстка:

* дефекты макета исправлены — доступность, отложенная загрузка, размеры
  картинок под CLS, лишний jQuery (полный список в
  [docs/questions.md](docs/questions.md));
* 323 мёртвые ссылки разведены по реальным страницам;
* собраны две страницы, которых не было в макете: «Спасибо» и выдача поиска;
* совпадение геометрии с исходным макетом проверено на пяти страницах
  в двух разрешениях.

Натянуто на WordPress:

* все страницы отдаются из CMS: главная, О студии, Дизайнерам, Покупателям,
  Вдохновение, Контакты, Политика, Избранное, Корзина, Спасибо, 404,
  каталог на /catalog/ и карточка товара /product/<slug>/;
* WooCommerce активен: категории Муралы и Фоновые обои, три тестовых товара
  с SKU и ценами (`tools/seed-woo.php`), штатные страницы корзины/checkout/
  кабинета Woo закрыты — на Этапе 1 их нет по ТЗ;
* каталог и карточка пока показывают разметку макета: живая подстановка
  товаров — следующий шаг, частично заблокирована вопросами из
  docs/questions.md;
* меню, ЧПУ и структура заводятся скриптом `tools/seed.php`, а не руками;
* галерея «Вдохновение» переведена в CMS: 25 плиток стали записями, снимки
  и подписи меняются в админке без правки вёрстки;
* совпадение с макетом проверено измерением геометрии на пяти страницах —
  все элементы до пикселя.

Тема и модель:

* каркас темы, шапка и подвал с настоящими меню WordPress;
* все 16 страниц нарезаны в шаблоны, пути к картинкам переписаны на тему;
* jQuery берётся штатный из WordPress;
* контент-модель: справочник материалов с ценой за м² и типом шва, таксономии
  фильтров, сущность «Заявка» со статусами NEW / SENDING / SENT / FAILED.

Работает сквозной сценарий покупателя:

* **каталог живой** — карточки из WooCommerce во всех трёх табах, цена
  «от N ₽/м²» из основного материала, счётчик честный
  (`tools/seed-catalog.php` наполняет тестовыми данными);
* **карточка товара** — реальные название, коллекция, описание, галерея;
  калькулятор по ТЗ п. 8: формула ((W+5)/100)×((H+5)/100), лимиты
  1–10000×1–6000 см, пересчёт при вводе и смене материала, округление до
  1 ₽;
* **корзина** — localStorage, страница показывает оба состояния макета,
  позиции с размерами/материалом/ценой, итог, удаление, очистка;
* **избранное** — localStorage, сердечки в каталоге и на карточке,
  страница избранного фильтрует сетку, состояния пусто/полно;
* **заявки** — модалки форм из макета отправляют в
  `POST /wp-json/okoyom/v1/lead`: Lead в CMS со статусами
  NEW → SENDING → SENT/FAILED, письмо менеджеру, атрибуция
  (utm/yclid/vkclid/referer/landing с первого визита), состав корзины
  и итоговая сумма, привязка к товару.

Дожато после (ТЗ п. 3.2, 7, 9.7, 11, 13):

* **ретраи заявок** — FAILED переотправляются кроном каждые 30 минут
  (до 5 попыток), в админке у заявки колонки статуса/суммы/окружения и
  ссылка «Переотправить»;
* **поиск** — Enter в поле панели фильтров ведёт на `/search/?q=…`,
  ищет по названию и SKU, пустая выдача со своим сообщением;
* **SEO-база** — JSON-LD (Organization, WebSite на всех страницах;
  Product + BreadcrumbList на карточке; LocalBusiness на контактах),
  noindex для поиска/корзины/избранного/спасибо, они же исключены из
  wp-sitemap.xml;
* **prefers-reduced-motion** — reveal-анимации отключаются по системной
  настройке;
* **всё локально** — Swiper, AOS и шрифты (вариативные Outfit + Playfair
  Display) отдаются со своего домена, внешних запросов на страницах ноль.
