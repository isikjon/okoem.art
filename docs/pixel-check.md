# Проверка «пиксель в пиксель»

Главное требование заказчика — не потерять визуал, который долго доводили.
Поэтому любая правка вёрстки проверяется измерением, а не на глаз: сравниваем
геометрию каждого элемента с исходным макетом от заказчика.

Проверка уже поймала две реальные поломки:

* атрибут `height` растягивал картинку с 835 до 3340 px там, где CSS задаёт
  только ширину — поехало 36 изображений из 66 на одной главной;
* атрибут `width` расширял логотип в шапке с 92 до 122 px и сдвигал всё
  меню на 15 px вправо.

Обе нашлись только измерением: на скриншоте первого экрана они не видны.

## Как запускать

Нужны две копии: эталон (исходный zip от заказчика, распакованный отдельно)
и текущая `macket/`. Поднимаем обе на своих портах:

```bash
cd /путь/к/эталону && python3 -m http.server 8891 --bind 127.0.0.1
```

```bash
cd macket && python3 -m http.server 8893 --bind 127.0.0.1
```

Порты должны различаться, а после правки CSS нужен новый порт либо сброс
кэша — причём с обеих сторон. Браузер держит `style.css` по адресу порта, и
устаревший файл на **эталонном** сервере однажды дал ложное расхождение на
двух страницах: эталон считался со старым CSS, реальная вёрстка была верной,
а полчаса ушло на поиск несуществующей поломки. Правило простое: правил CSS —
подними эталон на новом порту.

При натяжке на WordPress эталоном служит `macket/`, а сравнивать надо
адреса WP (`/`, `/about/`), а не файлы. WordPress сам добавляет `?ver=`
к своим стилям, поэтому его сторона от кэша не страдает.

## Чем измерять

Открыть любую из версий и выполнить в консоли. Скрипт грузит страницы в
iframe, дожидается всех картинок и считает хеш геометрии всех элементов.
Прогнать на обоих портах и сравнить хеши.

```js
(async () => {
  const H = s => { let h=2166136261; for (let i=0;i<s.length;i++){ h^=s.charCodeAt(i); h=Math.imul(h,16777619);} return (h>>>0).toString(16); };
  async function measure(page, width) {
    const f = document.createElement('iframe');
    f.style.cssText = `position:fixed;left:-9999px;top:0;width:${width}px;height:900px;border:0`;
    document.body.appendChild(f);
    await new Promise(r => { f.onload = r; f.src = page + '?v=' + Date.now(); });
    const d = f.contentDocument;
    for (const i of d.images) i.loading = 'eager';
    await Promise.all([...d.images].map(i => i.complete ? 1 : new Promise(r => { i.onload = i.onerror = r; })));
    await new Promise(r => setTimeout(r, 1200));
    const els = [...d.body.querySelectorAll('*')].filter(e => e.getClientRects().length);
    let sig = '';
    for (const e of els) { const r = e.getBoundingClientRect(); sig += `${e.tagName}|${Math.round(r.x)},${Math.round(r.y)},${Math.round(r.width)},${Math.round(r.height)};`; }
    f.remove();
    return { page, width, count: els.length, docH: Math.round(d.body.scrollHeight), hash: H(sig) };
  }
  const out = [];
  for (const p of ['index.html','catalog.html','card.html','contact.html','bag-2.html'])
    for (const w of [1440, 375]) out.push(await measure(p, w));
  return JSON.stringify(out);
})()
```

Хеши совпали — визуал не тронут. Не совпали — резать по чанкам: считать хеш
каждых 25 элементов, найти отличающийся кусок и сравнить в нём `tag.class|x,y,w,h`
поэлементно. Так обе поломки выше были локализованы за пару минут.

## Что проверка нашла при натяжке на WordPress

* потерялись инлайн-скрипты страниц — в макете они лежат после подвала, и
  первый вариант нарезки их просто не переносил. Без них не собирались
  слайдеры: на главной не хватало пяти элементов;
* не подключились шрифты Outfit и Playfair Display — их `<link>` был в
  `<head>` макета, а шапка темы собирается заново. На системных шрифтах
  меняются метрики, и заголовки переносятся по-другому;
* подвал на четырёх страницах (О студии, Покупателям, Дизайнерам, Контакты)
  шёл в макете с inline `margin-top: 0`, а подвал в теме общий;
* страница «Спасибо» не была прописана в карте шаблонов и отдавала пустую
  заглушку вместо вёрстки.

Ни одно из этого не видно на скриншоте первого экрана.

## Чего проверка не ловит

Слайдеры. При принудительной загрузке картинок Swiper иногда не успевает
разложить слайды, и позиции второго и третьего слайда отличаются между
прогонами разных версий, хотя видимый слайд одинаков. Такое расхождение
проверяется контрольным опытом: измерить одну и ту же версию дважды. Если
внутри одной версии стабильно, а между версиями нет — сверять скриншотом.

Цвета, шрифты и тени геометрией не измеряются. Их сверяем скриншотами
ключевых страниц.
